# Igroteka — безопасность данных в GitHub

Для публикации была **создана новая пустая SQLite-база из схемы оригинала**, а не отредактирована копия с 640 играми. Это исключает остатки ранее удалённых персональных значений в свободных страницах SQLite.

- В `seed-data/igroteka.sqlite3`: **0 игр**, **0 записей в корзине**, чистые `metadata` и `settings`.
- `data/igroteka.sqlite3` не отслеживается Git, а локально создаётся при запуске `INIT-DEMO-DATA.cmd`.
- Резервные копии SQLite, файлы WAL, секреты и локальные артефакты не включаются в репозиторий.
- Контрольная сумма очищенной БД (SHA-256): `64699fdff58356482ab93effe6f3601d267b442306a0e10d8a0c29a5091d78c4`.
- Исполняемый `Igroteka.exe` из оригинального релиза не менялся. Только две внешние SQLite-базы заменяются чистыми копиями.

В исходном GitHub-пакете для шрифтов используются локально установленные в Windows начертания Inter вместо вложенных бинарных файлов. Это может слегка изменить внешний вид на компьютере без установленного Inter. Сама портативная EXE-сборка не пересобиралась.

## Сборка из исходников

После клонирования сначала запустите `INIT-DEMO-DATA.cmd`, затем `npm ci` и `npm run verify`. Команда инициализации никогда не перезаписывает уже существующую `data/igroteka.sqlite3`.

**Не добавляйте личные базы принудительно через `git add -f`.** Для резервных копий вашей настоящей библиотеки используйте отдельное локальное хранилище, а не Git.
